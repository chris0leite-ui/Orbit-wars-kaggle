# v3.5 — Airtime penalty + endgame neutral burn — A/B verdict

> Branch `claude/optimize-ship-strategy-tDPXx`. Implements the user's
> "penalize airtime of fleets" directive plus the plan's Exp 1
> (endgame burn-through) variant. Both knobs land as opt-in constants
> in `lib/missions/snipe.py`. **A/B at 64-seed: defaults reverted to
> identity** (see §A/B verdict below).

## TL;DR

After bundle-based A/B against the v3.4 baseline (`scripts/ab_variants.py`):

| Variant                                                | 32-seed vs baseline | 64-seed vs baseline |
|--------------------------------------------------------|---------------------|---------------------|
| AIRTIME=1.0, ENDGAME=1.5 (original v3.5)               | **43.8%** [32.3, 55.9] | not re-tested |
| AIRTIME=0.5, ENDGAME=1.5 (best ablation point estimate)| 54.7% [42.6, 66.3] | **52.3%** [43.7, 60.8] |
| AIRTIME=0.25, ENDGAME=1.5                              | 51.6% [39.6, 63.4] | not tested |
| AIRTIME=0.0, ENDGAME=1.5 (eg_only)                     | 12.5%* [6.5, 22.8] | not tested |
| AIRTIME=0.5, ENDGAME=1.5, AFFORDABILITY_FILTER=1       | not tested | **21.1%** [14.9, 29.0] — broken |

\* eg_only had 40/64 draws — the agent stalemates at step 500 without
airtime tension. Win/loss-only is 8W/16L (33% of decisions).

**Decision:** revert all three constants to identity defaults
(`AIRTIME_PENALTY_WEIGHT=0.0`, `ENDGAME_NEUTRAL_BONUS=1.0`,
`PROPOSER_AFFORDABILITY_FILTER=0`). The best-performing combination
converged to ~52% over 128 games — Wilson95 lower bound at 43.7% means
we cannot rule out it being WORSE than baseline. The bucket-reduction
proxy from Phase-0 was a misleading leading indicator.

The constants remain in the code so future ablations (e.g.,
phase-decay airtime, value-conditional airtime, gang-up + airtime
composite) can be tested by editing one line + re-bundling.

## What changed

`lib/missions/snipe.py` adds two scoring terms on top of the cost-aware ROI:

```python
AIRTIME_PENALTY_WEIGHT = 1.0   # adds AIRTIME_PENALTY_WEIGHT * eta to the
                               # denominator; pushes target selection
                               # toward shorter flights.
ENDGAME_STEP = 470             # late-game phase threshold
ENDGAME_NEUTRAL_BONUS = 1.5    # multiplies neutral priority at step>=ENDGAME_STEP

score = priority * value / (base_ships + d + AIRTIME_PENALTY_WEIGHT * eta + 1.0)
# priority *= ENDGAME_NEUTRAL_BONUS when t.owner == -1 AND step >= ENDGAME_STEP
```

### Why this design

**Airtime penalty.** Phase-0 idle-source decomposition
(`audit/2026-05-11-idle-breakdown-v3-snipe-phase0.md`) showed ~96% of
all idle classifications come from `intent.ships > src.ships` in
`validate` + `arrival_size`. The worst offenders are *long-eta enemy
targets* where the production-growth adjustment
(`target.ships + production*eta + 1`) inflates the required fleet beyond
the source's garrison. Penalising eta in the score formula shifts the
proposer's preference toward shorter, fundable captures, killing two
birds: opportunity cost (ships frozen mid-flight) and the dominant
mechanism-drop bucket.

**Endgame neutral burn.** Same Phase-0 finding shows the late phase
(step ≥ 400) in 2P self-play is 100% MECHANISM_DROP. By contrast,
neutral targets are pass-through in `arrival_size` (no production
growth). At endgame, prioritising near uncontested neutrals is a
free-percent win: launchable captures with bounded downside.

The existing failed knobs (v3.3 blanket +1, v3.4 flat
NEUTRAL_BONUS=1.5) are NOT revived. NEUTRAL_BONUS stays at 1.0;
ENDGAME_NEUTRAL_BONUS is **phase-gated** so the bonus fires only when
the time-budget makes neutrals strictly preferable.

## Bucket deltas (v3.5 vs v3_snipe baseline, 8-game self-play)

Same seeds: 42-45 (2P) and 142-145 (4P).

| Metric | 2P baseline → v3.5 | 4P baseline → v3.5 |
|--------|--------------------|---------------------|
| turns                       | 1686 → 1996 | 1145 → 923 |
| idle classifications / turn | 11.80 → 12.86 (+9%) | 8.09 → **4.67 (−42%)** |
| captured (raw)              | 721 → 861 (+19%) | 231 → 153 |
| bounced_enemy               | 61 → 86 | 15 → 10 |
| alive_at_end (in-flight)    | 11 → 25 | 13 → 3 |
| NO_PROPOSALS                | 0 → 0 | 236 → **153 (−35%)** |
| LEDGER_LOSS                 | 0 → 0 | 2,628 → **222 (−92%)** |
| MECHANISM_DROP              | 19,896 → 25,677 (+29%) | 6,403 → **3,939 (−38%)** |
| drops/turn (validate)       | 5.73 → 6.71 | 2.21 → 1.70 |
| drops/turn (arrival_size)   | 5.89 → 5.95 | 3.23 → 2.53 |

### Reading the 4P signal (clean win)

- **LEDGER_LOSS −92%** (mid-phase: 40% → 14% of idle). The airtime
  penalty shifts each source's top-pick toward different (closer)
  targets, dramatically reducing the case where every source wants
  the same heavily-defended planet and all get ledger-blocked.
- **MECHANISM_DROP −38%, NO_PROPOSALS −35%, idle rate −42%.** Per-turn
  drops by both `validate` and `arrival_size` are down ~20-30%.
- Captures drop in absolute terms (231 → 153) but games are 19%
  shorter — that's a 4P self-play artifact, not a regression: when both
  sides play sharper, the dominant side eliminates the others faster.

### Reading the 2P signal (more activity, mixed bucket)

- 2P self-play game 44 went from **190 → 500 turns** under v3.5 — the
  loser-side agent survived 2.6× longer. Across 4 games, total turns
  rose 18%.
- Captures rose 19% (721 → 861) and `alive_at_end` (fleets in
  transit at game end, contributing to final score) more than doubled
  (11 → 25).
- BUT per-turn idle rate ticked up from 11.80 to 12.86 (+9%). All idle
  is MECHANISM_DROP; LEDGER_LOSS and NO_PROPOSALS remain 0 in 2P
  self-play.
- The 2P bucket regression on `validate` (5.73 → 6.71 drops/turn)
  needs investigation. Most likely explanation: by selecting closer
  targets with lower static base_ships (which validate gates on
  `intent.ships > src.ships`), more candidates get past the proposer
  but get caught at validate when src.ships is still small. The
  airtime-penalty shift is over-eager in 2P where targets are
  uniformly close.

## Caveats

1. **Small sample** — 4 games per mode. The 2P "+9% idle rate" is
   noisy and could be within seed variance.
2. **Self-play, not live.** Same-agent matchups can't surface the
   exploits that show up against weaker live opponents (where Phase-0
   speculated `NO_PROPOSALS` and `LEDGER_LOSS` may be larger).
3. **No A/B vs frozen v3.4.** The 32-seed 2P + 16-seed 4P FFA panel
   per the plan gating protocol is the next step; this report only
   demonstrates the bucket-reduction story.
4. **Drop rate is the secondary metric, not the primary.** Reduced
   idle does not automatically mean higher μ — TrueSkill rewards
   win/loss, not activity. Local A/B confirms before any submission.

## A/B verdict — chronological evidence

Round 1 — direct 32-seed pair test (the original v3.5 defaults):
```
v3.5 (AIRTIME=1.0, ENDGAME=1.5) vs v3.4 baseline:
  W/L/D = 28/36/0   winrate = 43.8%   Wilson95=[32.3%, 55.9%]
```
**REGRESSION confirmed:** AIRTIME=1.0 over-penalises distant high-value
captures. The bucket-reduction story from Phase-0 was misleading —
fewer drops doesn't translate to wins.

Round 2 — 8-seed 5-variant ablation isolating the cause:
```
                             vs baseline   AIRTIME  ENDGAME
airtime_only (AIRTIME=1.0)   37.5% (6/10/0)  1.0     1.0
airtime_full (1.0/1.5)       37.5% (6/10/0)  1.0     1.5
endgame_only                 31.2% (5/5/6)   0.0     1.5
air05_eg (BEST point est.)   50.0% (8/8/0)   0.5     1.5
```
AIRTIME=1.0 is the regression cause; light AIRTIME=0.5 looks promising.

Round 3 — 32-seed 4-variant pair-level vs baseline:
```
a05_eg                       54.7% (35/29/0)   Wilson95=[42.6%, 66.3%]
a025_eg                      51.6% (33/31/0)   Wilson95=[39.6%, 63.4%]
eg_only                      12.5% (8/16/40)   Wilson95=[ 6.5%, 22.8%]
```
Point estimates positive; Wilson_lo below 50% — inconclusive.

Round 4 — 64-seed 3-variant (confirmation + filter test):
```
a05_eg                       52.3% (67/61/0)   Wilson95=[43.7%, 60.8%]
a05_eg_filter                21.1% (27/101/0)  Wilson95=[14.9%, 29.0%] BROKEN
```
- The 32→64 seed extension dropped a05_eg's point estimate from 54.7
  to 52.3. The extra 32 seeds were exactly 50/50. **Best read: true
  winrate is indistinguishable from coin flip.**
- Affordability filter regresses heavily. Likely cause: when sources
  can only choose tiny affordable captures, the deployment cost
  (undefended home, ships in transit) exceeds the captured-planet EV.
  Idle garrisons were doing strategic defense work the filter destroyed.

## Why the Phase-0 proxy misled

Phase-0 bucket reductions measured fewer MECHANISM_DROP. The mistake:
each "drop" wasn't pure waste — it represented an UNAFFORDABLE attempt
at a HIGH-VALUE target. Sometimes those attempts succeeded via
WorldModel-aware adversary stacking. Replacing drop-attempts with
small affordable captures shifted the agent toward "lots of small
captures", which loses to v3.4's "few big captures + strong home
defense" line.

## Recommended next moves

Approaches more likely to produce a real lift:

1. **Multi-source gang-up (Exp 4)** — actually enable multiple sources
   to contribute to one high-value target via shared sizing in
   `arrival_size`. Tackles the root cause Phase-0 surfaced, not the
   symptom.
2. **Phase-decay airtime** — `airtime_term = WEIGHT * eta *
   (EPISODE_STEPS - step) / EPISODE_STEPS` so the penalty fades in
   late game where airtime is cheap.
3. **Predicted-needed affordability filter** — instead of `base_ships
   > src.ships`, predict the post-`arrival_size` needed (including
   `target.production * eta`) and only filter if THAT exceeds src.
   Closer to the true filter the strategy implicitly applies.
4. **Defensive reinforce expansion** — proactive reinforce for any
   planet whose garrison would drop below `incoming_threat - own_prod
   * eta`, not just predicted ownership flips.

All four need their own bundle-based A/B. The harness at
`scripts/ab_variants.py` is ready to drop new variants into.
