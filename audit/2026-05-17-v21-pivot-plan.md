## Design — one focused change

**One file changed: `agents/v22/main.py`. Zero `lib/` changes.**

v22 starts as a copy of v15 (NOT v20 — v15 holds the floor and is our strongest base), with one substitution:

```python
# v15 / v20 line (v22 NOT this):
from lib.opp_model import lite_greedy_policy as _opp_policy

# v22 line:
def _opp_policy(obs):
    return _lite_greedy_with_counter_recapture(obs)
```

`_lite_greedy_with_counter_recapture` is defined inline in `agents/v22/main.py`:

```python
from lib.opp_model import lite_greedy_policy as _lite_greedy_offensive

def _lite_greedy_with_counter_recapture(obs):
    """lite_greedy + one defensive counter per turn per opp planet under
    incoming attack. Augments the offensive base — never replaces it —
    so the opp's expansion behavior is unchanged from what every
    other agent expects of lite_greedy.

    Counter-recapture rule (one per opp planet per turn):
      for each my-incoming-fleet f targeting opp planet P:
        let surplus = ships of opp planet S nearest to P with
                      garrison_S − 1 ≥ ships(f),
                      where S is within R=30 of P, S != P,
                      and S has not already emitted this turn.
        if S exists, emit [S, aim(P), ceil(ships(f)) + 1] from the opp.

    `obs` here is the OPP's seat observation (the policy is called per
    seat in the rollout). 'My' from the policy's POV is the seat whose
    obs is being scored; the function is symmetric.
    """
    out = list(_lite_greedy_offensive(obs) or [])
    # ... O(my-fleets × opp-planets) counter logic; ~30-50 LOC.
    return out
```

The implementation lifts the counter-recapture logic from v21's `_opp_actions_for_snap_with_counter` (which was inline in v21 for E2's hold-check) — that code already works and was verified by the v21 instrumentation gate. The only change is *where* it's called: previously only in the once-per-candidate hold-check; now in every rollout step.

**What v22 does NOT do:**
- No new `lib/opp_model.py` symbol added (zero blast radius for v7_X / v15 / v20).
- No E1 prefilter (falsified — explicit-rewrite friction).
- No E2 hold-check (subsumed: counter-recapture is now *in* the rollout, not after it).
- No joint-emit Patch A (falsified — n=32 = 31.2 %).
- No comet discount as a separate term (the rollout naturally penalises comet shots: comet planets de-spawn, my fleet vanishes, leaf F2 drops).

## Why this should work where v21 didn't

v15's rollout is the value function. Inputs the rollout sees → outputs Δ → chooser picks. v21 added filters AFTER the rollout, redundantly. v22 strengthens an input *to* the rollout — the opp's behavior — so the same chooser code now scores fragile captures more honestly.

Empirically: v15's `_favor` leaf is `(my_prod − opp_prod) × pv_horizon`. When opp recaptures my planet inside the rollout, the leaf sees `my_prod` drop and `opp_prod` rise — both terms swing against the candidate. This is the strongest possible signal for the chooser. The current weakness: lite_greedy doesn't counter, so captures look stickier in the rollout than in live games. Patch the opp; the chooser fixes itself.

## Wallclock budget

Counter-recapture logic per opp seat per rollout step: O(my-fleets × opp-planets). On a typical mid-game board (10 my fleets, 15 opp planets) = 150 checks each ~0.5 µs = 75 µs per step. Per-candidate rollout has ~30 steps × 75 µs = 2.25 ms of added overhead per candidate. At n_affordable = 30 candidates per turn, total added cost ≈ 70 ms — well within the 600 ms budget.

v21's E2 hold-check was 50–200 ms per candidate × 3 = 150–600 ms. v22 spreads the same cost over every rollout step at much lower per-call cost. Net: v22 should be **faster** than v21, not slower.
